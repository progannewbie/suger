## 假設與前提

| 項目 | 假設值 | 依據 | 風險 |
|---|---|---|---|
| 糖線寬 `bead` | 2.5 mm | **估計值,未實測** | 影響 Skill 2 取樣容差與毛筆視覺,實測後全鏈要重跑 |
| 粗細對比上限 | 4 倍 | 量測真跡 `images (1).jpeg` 得 p95/p5 = 4.0 | 超過此值糖絲可能斷 |
| 畫布平面度 | 視為理想平面 | 尚無治具 | 不平會造成線寬不均 |
| 工具中心點 | 已校正在噴嘴尖端 | **未做** | 未校正時 z=0 落在法蘭中心,差數十至一百餘 mm |
| 繪圖區 | 300 × 300 mm | 使用者指定 | 已納入 `plan.py --area` 檢查 |
| 控制器 | Kawasaki F60,已裝 Ethernet 選購板卡 | 使用者確認 | 無板卡則報 E4054 |

## 背景

糖畫是把熬好的糖漿拉成連續糖絲作畫。三個物理特性決定整個系統設計:

1. **糖流量固定** → 線寬 × 速度 = 常數。粗細只能靠速度控制,不能靠壓力。
2. **停頓會積糖** → 移動指令之間不能等待到位,否則每個停頓點留下一坨。
3. **抬筆會斷絲** → 每次抬筆是一個疤痕加一次斷線風險。

## 目標

- 輸入任意中文字或圖片,輸出手臂可執行的連續路徑。
- 保留書法的粗細變化與連筆特徵。
- 手臂端程式固定不變,所有決策在 PC 端。
- 上機前可離線驗證,不需連接手臂。

## 範圍

涵蓋:字形取得、描圖、路徑規劃、點數壓縮、運動規劃、通訊協定、手臂端執行、離線模擬。

## 不做什麼

- 不做熬糖、溫控、出糖機構的設計。
- 不做手臂的安全區設定與碰撞檢查(交由控制器原有機制)。
- 不做多手臂協同、輸送帶同步。
- 不追求行草字形。字形來源是楷書骨架,加牽絲只能做到連筆楷書。

## 系統說明

五個階段,四種產出格式。

```
輸入(字 / 圖)
  │
  ├─ Skill 1  text2path.py / img2path.py  → out.svg      筆劃中心線 + 每點粗細
  ├─ Skill 2  svg2points.py               → points.json  手臂平面座標
  ├─ Skill 3  plan.py                     → motion.json  動作計畫
  ├─           stream.py                  → 文字封包
  └─ TCP → arm/sugar_server.as            → 手臂動作
```

## 核心流程設計

### Skill 1 — 產生可畫的筆劃

**文字路線** 查 makemeahanzi 的 `graphics.txt`,取每一筆的中心線(median)與筆順。
座標為 1024 em box、y 軸朝上,與輸出慣例一致,不需翻轉。

處理鏈:Catmull-Rom 平滑 → 曲率計算 → 粗細曲線 → 牽絲連接 → 等弧長重取樣。

**圖片路線** 二值化 → 骨架化(Zhang-Suen) → 追蹤 → 去毛刺 → 合併 → 簡化。
參數全部由量到的線寬推導,不需手調。

### Skill 2 — 壓縮點數

判準:**取樣誤差小於糖線寬的四分之一就看不出來**。比糖線細的偏差被糖本身蓋掉。

四步:RDP 保幾何 → 強制保留速度換檔點 → 長段補點 → 過近點刪除。

第二步不可省略。毛筆粗細靠速度做,速度轉折處的點被抽掉則出鋒與牽絲一併消失。

### Skill 3 — 決定怎麼走

速度公式:`speed = clamp(draw_speed / width, draw_speed, max_speed)`

動作型態只用兩種:

| 情況 | 指令 |
|---|---|
| 筆劃內每一段 | `lmove` 直線插補 |
| 移到下一筆起點上方 | `lmove`(預設) / `jmove` |
| 下筆 | `lmove`,必須垂直 |
| 抬筆 | `ldepart`,沿工具 Z 軸退開 |

## 開發應注意重點以及應避開誤區

以下每一條都是實際踩過的。

### Kawasaki AS 語言

| 誤區 | 正確做法 | 出處 |
|---|---|---|
| 字串變數寫成 `pkt$` | `$` 在名字**開頭**:`$pkt` | 手冊 3.7 p.3-19 |
| `CASE $cmd OF` 用字串分派 | CASE 索引必須是數值,字串要用 IF 鏈 | 手冊 p.6-69 |
| `ANY:` 沒空格 | 會被當成標籤,要寫 `ANY` 或 `ANY :` | 手冊 p.6-70 |
| `$DECODE` 當作取第 n 欄 | 它會**消耗**原字串,取一欄要呼叫兩次 | 90210-1342DE p.56 |
| `BASE = TRANS(...)` | `BASE` 是指令不是變數 | — |
| 中文註解 | 編碼轉換會吃掉行尾換行,把下一行併進註解 | 實測,曾吃掉 `TCP_ACCEPT` |

### 運動控制

- **移動指令之間不可插入等待到位**。要停由 PC 端明確送指令。
- **`ACCURACY` 不可設 0 或過小**,否則逐點停,每個停頓積糖。建議 3~5 mm。
- **用不到 Motion Type 2**。手冊 4.5.4.2:分支介於兩個移動指令之間時退回 Standard。
  用迴圈餵點必定觸發,手冊自己的範例亦然。後果是短線段達不到設定速度,線會變粗。
  對策:放大 `ACCURACY`、提高 `--min-seg`。
- **關節插補的路徑不可預測**,空中移動用它要把抬筆高度拉足。

### 通訊

- 兩端都不加換行當封包結尾。AS 的傳送指令原樣送出,不補換行,用等換行的方式讀會卡死。
- 單封包上限 250 字元(手冊限 255,留餘裕)。

## 核心資料模型

### 筆劃向量圖 `out.svg`

兩層,以 `data-role` 區分:

```xml
<g data-role="preview">   視覺層,瀏覽器打開即可見
<g data-role="path">      權威層,Skill 2 只讀這層
  <path id="stroke1" d="M ..." data-widths="1.000,0.982,..."/>
```

座標:標準向量圖慣例,左上原點、y 軸向下、單位 mm。
`data-widths` 與路徑點逐點對齊,值域 0.28~1.20。

### 座標 `points.json`

```json
{
  "units": "mm", "size_mm": [W, H],
  "tolerance_mm": 0.625, "bead_mm": 2.5,
  "n_strokes": 4, "n_points": 373,
  "strokes": [[[x, y], ...], ...],
  "widths": [[1.0, 0.98, ...], ...],
  "dots": []
}
```

座標已轉為**手臂平面座標**:中心原點、y 軸向上、單位 mm。

### 動作計畫 `motion.json`

```json
{
  "base": [450, 0, -120, 0, 180, 0],
  "accuracy": 3,
  "n_moves": 137,
  "op_counts": {"lmove": 128, "brk": 3, ...},
  "speed_range": [60, 300],
  "est_seconds": 8.8,
  "moves": [
    {"op": "lmove", "x": -8.61, "y": 22.27, "z": 15, "v": 300,
     "why": "移到起點上方"},
    {"op": "sig", "n": 1, "why": "開糖閥"}
  ]
}
```

`why` 欄位讓審查時不必回頭翻程式碼。

## 介面契約

### 通訊協定

一行一個動作,逗號分隔,換行區隔,收到即執行。

| 指令 | 參數 | 意義 |
|---|---|---|
| `lmove` | x,y,z,v | 直線插補到原點偏移 (x,y,z),速度 v mm/s |
| `jmove` | x,y,z,v | 關節插補 |
| `ldepart` | d,v | 沿工具 Z 軸退開 d mm |
| `sig` | n | n 正數開、負數關 |
| `wait` | t | 停留 t 秒 |
| `brk` | — | 等動作到位 |
| `base` | x,y,z,o,a,t | 設定畫布原點 |
| `acc` | n | 設定精度 mm |
| `end` | — | 結束 |

回覆 `OK` 或 `ER`,不含換行。

## 錯誤處理與回退策略

| 情境 | 偵測 | 回退 |
|---|---|---|
| 字形資料無此字 | 查表失敗 | 印出缺字清單,跳過該字繼續 |
| 圖片無明顯描邊 | 前景比例 > 18% 或線寬 > 4px | 自動改用梯度輪廓 |
| 圖片一片空白 | 二值化後無前景 | 中止並提示改用反轉或指定門檻 |
| 筆劃數過多 | 超過上限 | 自動提高門檻重篩直到收斂 |
| 超出繪圖區 | `--area` 檢查 | 印出警告,不自動縮放 |
| 通訊錯誤 | 回傳碼非 0 | 手臂端不停止,PC 端中止並印出封包內容 |
| 手臂回 `ER` | 回覆非 OK | PC 端中止,印出該封包 |

## 可觀測性

| 觀測點 | 方式 |
|---|---|
| 每一關的數量變化 | 終端機輸出筆劃/點數/長度/時間 |
