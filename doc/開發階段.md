## Stage 2 — 出糖裝置與流量參數

**為什麼**:目前糖線寬 2.5 公釐是估計值,它同時決定第二關的取樣容差與粗細的視覺效果。
這個數字不準,前面每一關的參數都是猜的。

**檔案清單**

| 檔案 | 動作 |
|---|---|
| `doc/出糖參數.md` | 新增,記錄實測數據 |
| `sugar_arm/plan.py` | 依實測調整速度上下限預設值 |
| `sugar_arm/svg2points.py` | 依實測調整糖線寬預設值 |

### Codex instructions

```
專案已有完整的路徑產生流程,現在要用實測數據校正三個參數。

輸入:一組實測記錄,格式為 CSV,欄位為
  速度(mm/s), 溫度(攝氏), 實測線寬(mm), 是否斷線(0/1)

任務:
1. 寫 sugar_arm/calibrate.py,讀入實測 CSV,輸出:
   - 線寬與速度的關係曲線,並驗證是否符合「線寬 x 速度 = 常數」
   - 不斷線的最高速度
   - 不積糖的最低速度
   - 建議的糖線寬預設值、畫線速度預設值、速度上限倍率
2. 產出一張圖,橫軸速度、縱軸線寬,標出可用區間。
3. 把建議值寫進 doc/出糖參數.md,包含實測日期與條件。

限制:
- 只用 numpy 與 pillow,不要引入繪圖套件。
- 資料點少於 5 筆時要明確拒絕,不要硬擬合。
- 若實測不符合反比關係,要明說並給出可能原因,不要強行套公式。
```

### Claude Code instructions

```
背景:糖流量固定時,線寬與速度成反比。這是整個粗細控制的物理前提,
但還沒有實測驗證過。

任務:寫 sugar_arm/calibrate.py,吃實測資料,吐建議參數。

重點:
- 先驗證反比關係是否成立,再談建議值。如果實測不符合,老實說不符合,
  給出可能原因(溫度漂移、噴嘴口徑、糖的黏度),不要為了產出數字而硬擬合。
- 找出兩個邊界:跑多快糖絲會斷、跑多慢會積糖。可用區間就在這兩者之間。
- 建議的速度上限倍率不要超過 4。我們量過真跡的粗細對比是 4.0 倍,
  超過這個值不只是不像,而且做不出來。

產出圖表要能一眼看出可用區間在哪。

完成後把建議值寫進 doc/出糖參數.md,並說明如果採用會影響哪幾個檔案的預設值。
```

**測試**:用不同速度各畫一條 100 公釐直線,量測實際線寬,確認符合預測。

**完成定義**:糖線寬、畫線速度、速度上限三個數字有實測依據,並已更新到程式預設值。
