# 筆劃 SVG → 手臂座標點位 (Skill 2)

只做一件事:**在不失真的前提下,用最少的點表示這條路徑**。

上游是 Skill 1(`sugar-stroke`)的 SVG,下游是 Skill 3(動作型態、速度、通訊字串)。

## 「多少點才夠」有精確答案

不是憑感覺給一個點數。判準是:

> **取樣誤差小於糖線寬的四分之一就看不出來。**

比糖線更細的偏差會被糖本身蓋掉 —— 手臂走直線抄近路,但那條線被 2.5mm 寬的糖
覆蓋,肉眼分不出來。所以容差 `tol = bead / 4`,預設 0.62mm。

兩端的代價都很實在:

- **點太少** → 圓弧變多邊形,手臂在每個折點減速 → 一串等距糖疤,像蜈蚣
- **點太多** → 封包爆量(每包只能塞 250 字元)、控制器來不及、AS 行數失控

實測:四個字 937 點 → 373 點,**省 60%**,畫面看不出差別。

## 怎麼跑

```bash
PY=~/Documents/義大/.venv/bin/python
$PY ~/Documents/義大/sugar_arm/svg2points.py in.svg -o points.json --report
```

`--report` 會列出每一筆的精簡前後,值得每次都開。

## 精簡分四步

1. **RDP 保幾何** — 在容差內丟掉共線冗餘點。這一步就決定了大部分的減量。
2. **強制保留速度換檔點** — 毛筆的粗細是靠速度做的。如果 RDP 把速度轉折處
   的點抽掉,出鋒和牽絲的效果會一起消失。所以量化後的速度只要變了,那個點就留。
3. **長段再切** — 超過 `--max-seg`(預設 8mm)的段補點。太長的段速度沒地方
   漸變,而且手臂走太久沒有校正機會。
4. **過近點刪除** — 間距小於 `--min-seg`(預設 0.4mm)的點刪掉。手臂走不出
   這種精度,留著只是灌封包。

## 參數

| 參數 | 預設 | 什麼時候動它 |
|---|---|---|
| `--tol` | 糖線寬/4 | 幾乎不用動。真要動先量實際糖線寬 |
| `--bead` | 讀 SVG metadata | 實測糖線寬跟 Skill 1 假設不同時 |
| `--max-seg` | 8 | 毛筆變化太生硬 → 調小 |
| `--min-seg` | 0.4 | 封包還是太多 → 調大 |
| `--draw-speed` | 60 | 要跟 Skill 3 用同一個值 |
| `--speed-quant` | 20 | 粗細變化太階梯 → 調小(但點數會增加) |

`--draw-speed` 和 `--speed-quant` 在這裡只用來決定「哪些點是速度換檔點」,
不寫進輸出。Skill 3 會自己再算一次,兩邊要用同一組值。

## 驗收

**看點位分佈圖,不要只看點數。**

正確的樣子是**直線段稀、曲線段密**。如果整條路徑點距均勻,代表自適應沒生效
——通常是容差給太小,退化成等距取樣。

判斷順序:

1. **形狀有沒有走樣** — 圓弧變多邊形?轉角被切掉?
2. **點分佈對不對** — 直線稀、曲線密才對
3. **點數合不合理** — 一個 45mm 的字大約 60~120 點;超過 200 通常是容差給太小
4. **毛筆效果還在嗎** — 起筆粗、收筆細、牽絲最細。不見了就是第 2 步失效

## 失敗樣態

| 症狀 | 原因 | 處置 |
|---|---|---|
| 「找不到 data-role="path" 那層」 | 不是 Skill 1 的產出 | 先跑 `sugar-stroke` |
| 「path 含非 M/L 指令」 | SVG 來自別的工具,有貝茲曲線 | 先用 Skill 1 重跑,或先離散化 |
| 點數幾乎沒減少 | 容差太小,或路徑本來就都是曲線 | 確認 `--bead` 讀對了 |
| 粗細變化不見了 | 速度換檔點被抽掉 | 調小 `--speed-quant` |
| 線變成多邊形 | 容差太大 | `--tol` 調小,但別小於糖線寬/8 |

## 輸出格式(給 Skill 3 的契約)

```json
{
  "units": "mm",
  "size_mm": [83.0, 97.0],
  "tolerance_mm": 0.625,
  "bead_mm": 2.5,
  "n_strokes": 4,
  "n_points": 373,
  "draw_len_mm": 1072.0,
  "travel_len_mm": 147.0,
  "strokes": [[[x, y], ...], ...],
  "widths": [[1.0, 0.98, ...], ...],
  "dots": []
}
```

座標已經是**手臂平面座標**:中心為原點、y 軸向上、單位 mm。
Skill 3 只要再套上畫布原點 `base` 就能走。

`widths` 跟 `strokes` 逐點對齊,是 0~1.2 的相對粗細。Skill 3 用
「線寬 × 速度 = 常數」換算成每點速度。

## 交付時要講的三個數字

1. **點位精簡比例** — 937 → 373,省 60%
2. **實際用的容差** — 0.62mm,以及它等於糖線寬的幾分之一
3. **每筆的點數** — 太不平均代表某一筆有問題
