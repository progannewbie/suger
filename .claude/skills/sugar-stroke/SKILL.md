# 糖畫筆劃路徑 (Skill 1)

把輸入變成一條**手臂能連續走完的中心線**,輸出 SVG。

下游是 Skill 2(SVG → 座標)和 Skill 3(座標 → 動作/速度/通訊字串)。
這一關只負責「畫什麼、怎麼連」,不碰機台參數。

## 為什麼是中心線,不是輪廓

糖畫是一條糖絲連續拉出來的線畫。輪廓會把每一筆變成細長的封閉圈,
回頭那半條線多餘,而且糖有寬度,兩條線會黏成一片糊。所以一律取中心線。

## 走哪條路

**輸入是中文字** → `text2path.py`。這條路品質高很多:字形資料庫直接給
每一筆的中心線和正確筆順,完全不用描圖,今天所有二值化/骨架化的坑都繞過。

**輸入是圖片** → `img2path.py`。描邊乾淨的卡通線稿效果好;
行草書法、照片、粗筆相連的圖會糊掉,先警告使用者。

## 寫字(主線)

```bash
$PY $SA/text2path.py 台灣尚勇 --size 45 --cols 2 --brush --link char \
    --svg out.svg -o out.json --preview out.png
```

### --link 決定書體

| 值 | 效果 | 抬筆次數(4 字) | 何時用 |
|---|---|---|---|
| `none` | 楷書,筆劃分離 | ~50 | 要工整、要每筆清楚 |
| `char` | 行書,字內連筆 | **3** | **預設。糖畫最實用** |
| `all` | 草書,整幅一筆到底 | **0** | 使用者明講要「一筆到底」 |

牽絲(連接線)在書法裡不是瑕疵,是行草的正字標記,而且**照筆順連**,
不是找最近的端點 —— 這跟畫圖時的 Euler path 完全不同。

代價要講清楚:`char` 的牽絲約佔總畫線 40%,`all` 約 50%。

### --brush 毛筆粗細

糖流量固定,所以**線寬 × 速度 = 常數,要細就跑快**。粗細其實是速度曲線。

預設曲線經過實測校正(對照真跡量到的粗細對比是 4.0 倍):
起筆 1.00 → 行筆 0.78 → 收筆 0.30(出鋒),牽絲 0.28,轉折處靠曲率加粗到上限 1.20。

**不要把對比調超過 5 倍。** 不只是不像,而且做不出來 —— 8 倍代表手臂要跑到
畫線速度的 8 倍,糖絲會斷。要調就動 `--curve-gain`(轉折加粗)和 `--silk-width`。

### 常用參數

| 參數 | 預設 | 說明 |
|---|---|---|
| `--size` | 40 | 字高 mm |
| `--cols` | 0 | 每行幾字,0=不換行 |
| `--vertical` | 關 | 直式書寫 |
| `--bead` | 2.5 | 糖線寬 mm,影響預覽和螺旋間距 |
| `--curve-gain` | 0.80 | 轉折加粗強度,0=關閉 |
| `--step` | 1.2 | 等弧長取樣間距 mm |

`/` 可以手動換行:`"新年/快樂"`。

## 描圖(圖片)

```bash
$PY $SA/img2path.py 圖.jpg --width 110 --one-stroke --svg out.svg \
    -o out.json --preview out.png
```

參數會從量到的線寬自動推導,**先不要手動指定**。跑完看它印出的那行:

```
線稿 門檻 110 / 前景 6.1% / 線寬 2.9px -> eps 1.15 min-len 11.5 join 8.7 ...
```

`--one-stroke` 對圖片是**補連接線**(Euler path),不是牽絲。
柯基那張要補 31 條、佔總畫線 28%,臉上會多一個大 X。
複雜圖建議不要開,或先砍掉孤立的小元件。

## 驗收迴圈 —— 這才是這個 skill 的價值

跑完一定要**看 `--preview` 的 PNG**。預覽是用真實糖線寬渲染的,
所以看得出「線會不會糊在一起」,細線預覽完全看不出來。

判斷順序:

1. **形狀對不對** — 字缺筆?圖糊成一團?
2. **線會不會糊** — 平行線靠太近就要放大 `--size` 或調小 `--bead`
3. **筆劃數合不合理** — 一個字 10~15 筆正常;圖超過 60 筆就太碎
4. **牽絲會不會蓋住字** — `--link all` 常常會,退回 `char`

### 失敗樣態

| 症狀 | 原因 | 處置 |
|---|---|---|
| 「字形資料庫沒有 X」 | 罕用字/異體字 | 換字,或改用手寫圖片走描圖 |
| 圖片跑出一坨 | 走了 edge 模式(實心/漸層/照片) | 正常行為,但告訴使用者這種圖不適合糖畫 |
| 圖片一片空白 | 白線黑底沒被偵測到 | `--invert` |
| 筆劃爆到上百條 | 圖太雜 | `--max-strokes 40` 讓它自動收斂 |
| 線變成多邊形 | 簡化過頭 | 調小 `--eps` |
| 一個圓被切成好幾筆 | 舊 bug,已修 | 確認用的是最新版腳本 |

## 輸出格式(給 Skill 2 的契約)

SVG 有兩層,靠 `data-role` 區分:

```xml
<g data-role="preview">   <!-- 視覺:逐段變寬,瀏覽器打開就看得到毛筆 -->
<g data-role="path">      <!-- 權威:中心線 + 每點粗細 -->
  <path id="stroke1" d="M ..." data-widths="1.000,0.982,..."/>
```

**Skill 2 只讀 `data-role="path"`,忽略 preview。**

座標是標準 SVG 慣例:左上原點、y 軸向下、單位 mm。
轉成手臂座標要翻 y 並置中。

`<metadata>` 裡有 `sugar-strokes` / `sugar-points` / `sugar-draw_mm` /
`sugar-silk_mm` / `sugar-bead_mm` / `sugar-link`,Skill 2/3 可以直接讀。

## 交付時要講的三個數字

不要只說「做好了」。糖畫的成敗看這三個:

1. **筆劃數與抬筆次數** — 每次抬筆是一個糖疤 + 一次斷絲風險
2. **畫線長度 vs 牽絲長度** — 牽絲佔比超過 50% 畫面會亂
3. **預估時間** — 抬筆通常佔一半以上,講出來使用者才知道瓶頸在哪
