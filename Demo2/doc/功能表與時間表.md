## Stage 1 —— 茶壺模式動作計畫（F2）

**為什麼要另開一支而不是改 `plan.py`**：`sugar_arm/plan.py` 服務的是

**檔案清單**

| 檔案 | 動作 |
|---|---|
| `Demo2/plan_pot.py` | 新增，由 `sugar_arm/plan.py` 改寫 |
| `Demo2/out/*_motion.json` | 產出 |

### Codex instructions

```
專案：機械手臂用茶壺畫糖，Python 命令列工具，僅依賴 numpy 與 pillow。

參考檔案 sugar_arm/plan.py，它把座標檔轉成手臂動作計畫。
請在 Demo2/plan_pot.py 寫一支功能相近但簡化的版本。

差異如下，每一條都必須照做：

1. 移除所有糖閥相關動作。原版會產生 op 為 "sig" 的動作來開關糖閥，
   茶壺治具沒有閥門，這類動作一律不產生。
   連帶移除「等糖絲成形」與「等糖絲斷」的 wait 動作。

2. 姿態固定。--base 參數接受 x,y,z,o,a,t 六個數字，
   其中 o,a,t 是茶壺的傾角，整份輸出中不得出現任何姿態變更。
   若使用者只給三個數字，印出錯誤並中止，因為傾角是本治具的必要參數。

3. 路徑中間不得出現 BREAK。原版在筆劃結束時會放 brk，
   本版輸入永遠只有一條筆劃，brk 只在最末端離場前出現一次。

4. 速度恆定。原版依 widths 陣列調整每段速度，
   本版 widths 全為 1.0，所有 lmove 使用同一個 --speed 值。

5. ldepart 抬起動作只在整張圖畫完後出現一次，用於離場。

輸出 JSON 的頂層欄位沿用原版：source、base、accuracy、moves。

命令列參數：
  json            輸入的 points.json
  -o, --out       預設 motion.json
  --base          x,y,z,o,a,t，必填
  --speed         畫線速度 mm/s，預設 60
  --travel-speed  空中移動速度 mm/s，預設 200（重心外伸，比原版保守）
  --zup           離場抬起高度 mm，預設 20
  --accuracy      連續 blend 的精度 mm，預設 3.0

執行後印出：
  各類動作的數量、相對原點的最大 X 與 Y 偏移、預估總秒數。

限制：
- 不要 import sugar_arm 下的任何模組，Demo2 必須能獨立執行。
- 所有檔案讀寫明確指定 encoding="utf-8"。
- 不新增第三方套件。

測試：
- 對 Demo2/out/spiral.json 執行，用 grep 確認輸出中沒有 "sig"。
- 確認輸出中 "brk" 只出現一次。
- 確認預估秒數與 shapes.py 印出的畫圖時間相差在 1 秒內。
```

**驗收**：手臂繞壺嘴記號旋轉時記號不飄移；空跑螺旋全程無警報。

**風險**：高。圓弧壺嘴沒有明確尖點，校正可能反覆多次。

**回滾**：無法回滾，這關必須通過。若時間超過 11:30 仍未完成，
放棄精確校正，改用目視粗估的 TOOL 值，接受線條位置偏移。

## Stage 6 —— 實機試畫與調參（F8，機台，明日下午）

**步驟**

1. 壺裝糖，放電磁爐加熱到融化
2. 拿起壺，執行螺旋，全程碼表計時
3. 觀察：線連不連、粗細均不均、圈間有無沾黏、收尾滴糖落在哪
4. 依觀察調整 `--speed` 與傾角，重跑。每次調整都記錄
5. 螺旋穩定後，依序試蛇行波浪、五芒星

**調參方向**

| 現象 | 調整 |
|---|---|
| 線太粗、圈間沾黏 | 提高 `--speed`，或減小傾角 |
| 線太細、斷線 | 降低 `--speed`，或加大傾角 |
| 尖角積糖（五芒星） | 加大 `--accuracy` 讓轉角更圓滑 |
| 畫到一半凝固 | 縮小圖形，或提高速度 |

**驗收**：螺旋畫出連續可辨識線條，圈間不沾黏，全程 60 秒內。

**風險**：中。每次試畫都要回爐重加熱，節奏比預期慢。
建議前兩次先用水或糖漿試，不要一開始就用會凝固的糖。

**回滾**：參數調壞時，退回上一組記錄的參數。
