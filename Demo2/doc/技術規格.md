# Demo2 技術規格 —— 茶壺治具 × 三種基礎圖形

文件日期 2026-09-15
目標完成日 2026-09-16
適用範圍 Demo2/ 資料夾，與 `sugar_arm/`（毛筆寫字）互不共用參數

---

## 1. 系統邊界

### 1.1 納入

輸入一個圖形名稱與參數，輸出機械手臂能一筆連續走完的平面座標，
經 Ethernet 傳給 Kawasaki RS07L，由固定傾角的茶壺流出糖漿畫成圖案。

### 1.2 排除（本次明確不做）

| 項目 | 理由 |
|---|---|
| 糖閥門 DO 訊號 | 茶壺無閥，流量由傾角決定 |
| 傾角動態變化 | 傾角一變，壺嘴位置就漂移，工具中心點要重算 |
| 抬筆／斷筆／多筆劃 | 斷流必牽絲，無閥無法乾淨斷開 |
| 自動加熱、手臂自行回爐 | 需要額外的爐面定位校正，不在一天內 |
| 中文字圖形 | 筆劃間必須抬筆，與「不抬筆」前提衝突 |
| Windows 移植 | 現場用 macOS，不是本次瓶頸 |

### 1.3 與第一次 DEMO 的物理模型差異

| 面向 | 第一次（sugar_arm） | 本次（Demo2） |
|---|---|---|
| 手臂 | Kawasaki F60 | Kawasaki RS07L（控制器同 F60） |
| 出糖 | 噴嘴 + 糖閥 | 茶壺，鎖在法蘭面，無閥 |
| 流量 | 開關閥控制 | 傾角控制，本次鎖定 |
| 線寬 | 線寬 × 速度 = 常數，速度變則粗細變 | 流量固定 → 速度固定 → 線寬均一 |
| 筆劃 | 多筆劃，中間抬筆 | 單筆劃，全程不抬筆 |
| 加熱 | 無 | 電磁爐，人工 |

**這是本規格最重要的一句話**：第一次 DEMO 的「線寬 × 速度 = 常數」公式在本次退化成
「速度恆定、線寬恆定」。粗細控制這個自由度被刻意放棄，換取工具中心點只需校正一次。

## 2. 資料流

```
圖形參數（螺旋 / 波浪 / 五芒星）
   │
   ├─ shapes.py      → points.json   平面座標，曲率自適應取樣
   ├─ plan_pot.py    → motion.json   動作計畫，無閥訊號，姿態鎖定
   └─ stream.py      → TCP 字串      一行一個動作
                       ↓
        Demo2/arm/pot_server.as      收字串 → 照字串講的去動
```

`shapes.py` 取代了第一次 DEMO 的 Skill 1（字→SVG）與 Skill 2（SVG→座標）兩關。
三種圖形都是數學曲線，直接由參數式算座標，不需要向量圖中介，也不需要描圖。

## 3. 介面契約

### 3.1 points.json

與 `sugar_arm/svg2points.py` 的輸出格式完全相同，確保下游可共用。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `units` | string | 固定 `"mm"` |
| `size_mm` | [float, float] | 圖形外接矩形寬高 |
| `source_shape` | string | `"spiral"` / `"wave"` / `"star"` |
| `tail_mm` | float | 收尾沿切線外拉長度 |
| `n_strokes` | int | 本次恆為 `1` |
| `n_points` | int | 座標點總數 |
| `draw_len_mm` | float | 路徑總長 |
| `travel_len_mm` | float | 本次恆為 `0.0`（不抬筆即無空走） |
| `widths` | [[float]] | 本次全為 `1.0`，線寬均一 |
| `strokes` | [[[x, y]]] | 座標陣列，中心原點、y 軸向上、單位 mm |

**座標系**：原點為工作區中心，x 向右、y 向上，與手臂平面一致。
這與 SVG 的「左上原點、y 向下」不同，`shapes.py` 直接產生手臂座標，不做轉換。

### 3.2 motion.json（plan_pot.py 輸出）

| 動作 | 欄位 | 說明 |
|---|---|---|
| `lmove` | `x, y, z, v` | 直線插補到指定點 |
| `ldepart` | `d, v` | 沿工具軸抬起 d 公釐 |
| `end` | — | 路徑結束 |

**本次不產生 `sig` 動作**（糖閥訊號），也**不產生筆劃間的 `wait`**。
`brk`（BREAK）僅在最末端離場前出現一次，路徑中間絕對不放 —— 每停頓一次糖就積一坨。

頂層欄位 `base` 為 `x,y,z,o,a,t` 六元組，其中 `o,a,t` 即**固定傾角**，
整份 motion.json 中不再出現任何姿態變更。

## 4. 取樣演算法

### 4.1 曲率自適應

弦長 `s` 對半徑 `R` 的圓，弓高約 `s² / (8R)`。令弓高等於容差 `tol`：

```
s = √(8 · R · tol)     再夾在 [min_seg, max_seg] 之間
```

直線段 `R → ∞`，步長取 `max_seg`；急彎 `R` 小，步長收斂到 `min_seg`。

預設 `tol = 0.3 mm`、`max_seg = 8 mm`、`min_seg = 0.8 mm`。

**容差合理性**：糖線寬估計 2~3 mm（假設 A4，未量測）。0.3 mm 的幾何誤差
約為線寬的 1/10，肉眼不可辨。若明天實測線寬明顯小於 2 mm，需調低 `tol`。

### 4.2 折線特例

五芒星是折線不是曲線，曲率在頂點為無限大、在邊上為零，公式失效。
改用專用路徑：**頂點必定保留**，長邊依 `max_seg` 均分。

### 4.3 收尾外拉

結束時把壺轉正斷流，壺嘴必定滴糖。所有圖形在終點沿切線方向外拉 `tail`
（預設 10 mm），使滴糖落在圖案之外。

## 5. 時間預算（硬限制）

茶壺離開電磁爐約 60 秒後糖凝固。這是整個系統唯一的硬性即時限制。

| 動作 | 預估秒數 | 來源 |
|---|---|---|
| 離爐、抬高、移到工作區上方 | 5 | 假設 A2 |
| 下降到起筆高度 | 3 | 假設 A2 |
| **實際畫圖** | **≤ 40** | 由 `draw_len / speed` 計算 |
| 抬起、離場 | 3 | 假設 A2 |
| 回電磁爐 | 5 | 假設 A2 |
| 緩衝 | 5 | — |
| 合計 | 61 | |

`shapes.py` 內建 `--limit`（預設 45 秒）。預估時間超過上限時印出警告，
並算出「要多快才畫得完」，但**不阻止產生檔案** —— 判斷權留給操作者。

### 5.1 三種圖形的實測預算（速度 60 mm/s）

| 圖形 | 尺寸 | 路徑長 | 點數 | 預估時間 | 緩衝 |
|---|---|---|---|---|---|
| spiral | 97 × 91 mm | 920 mm | 123 | 15.3 s | 29.7 s |
| wave | 101 × 58 mm | 483 mm | 67 | 8.0 s | 37.0 s |
| star | 95 × 100 mm | 486 mm | 62 | 8.1 s | 36.9 s |

三者都遠低於上限，代表**時間不是瓶頸，現場可放心加大尺寸或圈數**。

## 6. 狀態與持久化

本系統無長駐狀態、無資料庫、無使用者帳號。所有狀態都是檔案：

| 狀態 | 存放 | 生命週期 |
|---|---|---|
| 圖形座標 | `Demo2/out/*.json` | 每次執行覆寫 |
| 預覽圖 | `Demo2/out/*.png` | 每次執行覆寫 |
| 動作計畫 | `Demo2/out/*_motion.json` | 每次執行覆寫 |
| 工具中心點校正值 | 手臂控制器內的 TOOL 變數 | 常駐於控制器，斷電不失 |
| 工作區原點 | `plan_pot.py --base` 參數 | 記錄在 `Demo2/doc/現場參數.md` |

**校正值不存在程式裡**，存在手臂控制器。這代表換一台手臂就要重新校正，
也代表程式端不需要處理校正值的讀寫與版本。

## 7. 錯誤處理

| 情況 | 偵測方式 | 處置 |
|---|---|---|
| 預估時間超過 45 秒 | `shapes.py` 計算 | 印警告與建議速度，仍產出檔案 |
| 座標超出手臂工作範圍 | `plan_pot.py` 印最大偏移 | 操作者比對 RS07L 規格自行判斷 |
| TCP 連線失敗 | `stream.py` socket 例外 | 印出主機與連接埠，中止 |
| 手臂端收到格式錯誤字串 | AS 程式解析失敗 | 停在原地不動，不繼續執行 |
| 糖在畫到一半凝固 | 無法自動偵測 | 人工中止，壺回爐重加熱 |
| 壺嘴滴糖污染圖案 | 無法自動偵測 | 靠收尾外拉降低機率，其餘靠目視 |

**沒有自動緊急停止**。人必須站在手臂旁邊，手放在急停鈕上。

## 8. 驗收條件

### AC-1 圖形產生
- 三種圖形各自產出 `points.json` 與預覽 PNG，程式結束碼為 0
- `n_strokes` 為 1、`travel_len_mm` 為 0、`widths` 全為 1.0
- 預覽圖上起點、終點、實際座標點三者可分辨

### AC-2 動作計畫
- `motion.json` 中不含任何 `sig` 動作
- `base` 的 `o,a,t` 三個姿態角在整份檔案中不變
- `brk` 僅出現於離場前，路徑中間無 `brk`

### AC-3 手臂端
- AS 程式載入 RS07L 控制器，0 errors
- 不裝糖、不出糖的情況下空跑三種圖形，路徑完整走完不報警

### AC-4 實機畫糖
- 螺旋畫出可辨識的連續線條，圈與圈之間不沾黏
- 線寬肉眼判斷大致均一，無明顯粗細跳變
- 收尾的滴糖落在圖案輪廓之外

### AC-5 時間
- 從壺離爐到壺回爐，全程不超過 60 秒（碼表計時）

## 9. 邊界與濫用案例

| 案例 | 行為 | 處置 |
|---|---|---|
| `--turns 0` | 螺旋退化成一個點 | 產出 2 點路徑，不當機；操作者應自行避免 |
| `--r0 > --r1` | 螺旋由外往內 | 允許，但違反 D8 決策，滴糖會落在中心 |
| `--speed` 極小（如 1） | 預估時間爆表 | 警告觸發，操作者應察覺 |
| 圖形尺寸大於工作範圍 | 手臂執行中撞限位 | `plan_pot.py` 印最大偏移供人工比對，**無自動保護** |
| 壺沒裝糖就執行 | 手臂照走，畫不出東西 | 無偵測，靠目視 |
| 電磁爐忘記關 | 糖過熱焦化 | 不在系統範圍，人工負責 |
| 手臂執行中有人靠近 | 無防護 | **必須圍起工作區，人員不得進入** |

最後一項不是軟體問題，但是本次 DEMO 最高風險項。

## 10. 可觀測性

程式端每一步都印出可核對的數字：

- `shapes.py`：尺寸、路徑長、點數、預估時間、剩餘緩衝
- `plan_pot.py`：各類動作數量、速度範圍、相對原點的最大偏移、總秒數
- `stream.py`：送出的每一行字串、手臂端回應

**現場必須用碼表獨立計時**，不能只信程式的預估值 —— 預估值建立在假設 A2 上，
尚未經過任何量測。

## 11. 非功能需求

| 項目 | 要求 |
|---|---|
| 相依套件 | 僅 numpy 與 pillow，不新增 |
| Python 版本 | 3.11 以上 |
| 執行平台 | macOS（現場用機） |
| 檔案編碼 | 所有讀寫明確指定 utf-8 |
| 模組化 | `Demo2/` 不 import `sugar_arm/` 任何模組，兩者獨立演進 |
| 可回滾 | 每個開發階段獨立 commit，可單獨還原 |

**為什麼刻意不共用程式**：兩者物理模型不同（有閥 vs 無閥、線寬可變 vs 均一）。
共用會讓任一邊的參數調整意外影響另一邊，在只有一天的情況下不值得冒這個險。
